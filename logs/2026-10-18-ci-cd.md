## Implemented scope

The branch adds identical non-root Java 25 local/Vercel container definitions,
an opt-in GitHub Actions pipeline and a manual rollback workflow. Pull requests
test/package the application, review dependency changes, scan committed history
for secrets and build the deployment container. When explicitly enabled with
team-owned platform configuration, internal pull requests receive a Preview
deployment and merges to `master` receive a staged Production candidate. Health,
login and an authenticated safe read are smoke-tested before a protected
Production environment may promote the exact candidate without rebuilding.

The public `/health` endpoint checks application/database readiness, returns
only `UP` or `DOWN`, disables caching and exposes no connection diagnostics. The
container binds Vercel's `PORT`, honors proxy headers and shuts down gracefully.
All third-party GitHub Actions are pinned to immutable revisions; downloaded
Gitleaks is versioned and checksum-verified.
